# Adversarial audit, 2026-10-28

Five independent reviews of the plugin (collector, Steampipe layer and tests) and the mod (core controls and dashboard, hardening and supply chain, framework views), each trying to refute that a control proves its title. The lead verified the highest-impact findings against the code and Anthropic's docs. Live spot checks: 18 of 20 verdicts matched the filesystem; the two mismatches are findings P5 and M9 below.

This file is the work list for chunks 1 to 4. A finding is closed when its fix has a fixture test and, where it encodes Claude Code behaviour, a docs citation.

Status key: **[closed chunk 1]** fixed in plugin commit "Chunk 1: settings truth" (2026-10-28) with a fixture in `pkg/posture/posture_test.go`; **[closed, uncommitted]** fixed in the working trees of both repos on 2026-10-28 with a test or fixture (plugin CHANGELOG "Unreleased" says how), not yet committed; **[fixed, no fixture yet]** changed but not yet exercised by a test, so not closed by this file's rule; everything else is open.

## Decision taken

The framework benchmarks (`controls/frameworks/`, 14 views, ~120 benchmarks) and the 22 per-framework dashboard pages were removed from `main` (first kept on a `frameworks-archive` branch, which was itself removed when the repository was re-created on 2026-10-29). Reason: padding (section F below), no scanner in the field maps beyond OWASP, and the mapping work was consuming effort that belongs to data correctness. The mod now has one benchmark (`agentreach`, eight groups) and one dashboard. Framework tags on controls stay as documentation; `docs/frameworks.md` lists where each control sits.

## External reviews and the merged order (2026-10-28)

Two outside source reviews agreed with the direction and added work. Findings verified against the code: reach columns are modelled from configuration on top of a `user_process` probe; the path product joins legs by agent only; `collect_errors` is read by nothing; MCP `args`, `url` and hook `command` are stored raw; instruction-file signals feed the untrusted leg as verdicts. New asks: an evidence type on every verdict, observed reach through Anthropic's `srt`, detection or declaration of controls outside the agent (egress proxy, devcontainer, EDR), integrity outcomes, outcome-based control definitions, one implementation per check, Codex before the schema hardens, snapshots a fleet can ship, SDK v6.

Where each check lives: the three legs and the path product move into Go and come out as `agentreach_path`; the mod reads that table and never re-derives a leg. Hardening checks stay in SQL. A check has exactly one implementation.

Evidence vocabulary, one per column: `configured` (read from a settings file), `observed` (a probe saw it), `inferred` (derived by agentreach from configured plus observed), `unknown` (could not be assessed).

Order:

1. SDK v6 (Go 1.26 stays; v6 requires it).
2. Snapshot envelope (schema, collector version, snapshot id, host, time); redaction of MCP args, url and hook command; a not-assessed control on `collect_errors` that gates the dashboard headline.
3. Reach truth: `sandbox_enforced`, bypass reasons (unsandboxed retry, missing runtime, `excludedCommands`), `allowRead`; then P6, P7, P8, P11, P14 to P17.
4. Paths in Go (`agentreach_path`, evidence per edge), parity with the 1,827-path baseline, then mod honesty: candidate paths, review signals, coverage wording, M1 to M17, integrity outcomes.
5. Codex collector, minimal; Claude Code controls filter `agent = 'claude_code'`; Codex reach is `unknown` until modelled. Done 2026-10-28: Codex sandbox, approvals, trust, network, reads and paths are modelled (plugin `codexmodel.go`; fixture fx-codex); hooks, skills, plugins, local services and write targets are not.
6. Observed mode through `srt` with agentreach's translation of the effective settings.
7. Environment controls: proxy variables, container markers, declared controls in connection config.
8. CLI with JSON and SARIF, exit codes, snapshots; plugin reads a folder of snapshots.
9. Outcome-based spec with stable ids and coverage (automated, partial, manual).
10. Skill-only Claude Code plugin; the SessionStart hook ships as an opt-in user-settings snippet because agentreach counts plugin hooks as an exit.

Out of this pass: an osquery extension.

## P. Plugin (collector and tables)

Verdict-changing, verified by the lead:

- **[closed chunk 1] P1 Secret values reach tables.** `agentreach_setting.value` carries every `env.*` leaf of settings.json raw (`claudecode.go` ingestSettings skips only `hooks.*`). MCP `args` and `url`, full hook `command` text and full Bash allow-rule text are also raw. Fix: redact `env.*` and `*Helper` values to a boolean from `looksLikeSecret`; classify and redact `args`, `url`, `command`.
- **[closed chunk 1] P2 Managed tier merged backwards.** `c.managed = mergeSettings(c.remote, c.managedFile)` lets the file win and merges both. Docs (managed-settings, "How Claude Code combines managed sources"): remote first, then MDM plist, then `managed-settings.d/*.json` merged with `managed-settings.json`; first source with a policy key wins unless `managedSourcesBehavior = merge`. Drop-ins, MDM, `managed-mcp.json` and managed CLAUDE.md are never read. An empty `{}` remote file counts as "managed settings present".
- **[closed chunk 1] P3 Project and local scope ignored for effective rules.** Residual: a project rule now protects that project's files only; home-directory files are still judged by managed and user rules, which is the correct worst case across projects. `computeEffective` keeps managed and user only; `fsmatch` returns false for every `<cwd>` resolution. Docs: project settings can set `sandbox.enabled` and `denyRead`; relative deny patterns such as `Read(.env)` match at any depth under the working directory. Fix: resolve relative rules against each project's directory and include project and local rows keyed by project.
- **[closed, uncommitted] P4 Enabled is not enforced.** Reach treats a denyRead under an enabled sandbox as a hard block. Docs (sandboxing): failed commands may retry unsandboxed unless `allowUnsandboxedCommands` is false; a missing runtime runs commands unsandboxed unless `failIfUnavailable`; `excludedCommands` bypass; `allowRead` re-opens paths inside a `denyRead` region. Fix: add `sandbox_enforced` to `agentreach_agent`, honour `allowRead` and `excludedCommands` in reach.
- **[closed chunk 1] P5 MCP approvals in settings files invisible.** Approvals are read only from `~/.claude.json` `projects[dir]`. Live: four project directories carry `enabledMcpjsonServers` / `disabledMcpjsonServers` in `.claude/settings.local.json` and the table reports `enabled` null. `enableAllProjectMcpServers` is read from user scope only. Fix: resolve managed > local > project > user, then `~/.claude.json`.
